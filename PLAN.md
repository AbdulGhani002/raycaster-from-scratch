# MAQUIS 1944 — Design & Build Plan

A tactical WWII shooter built on this repo's from-scratch raycaster.
You are a French resistance fighter in occupied Normandy, 1944, running
sabotage and ambush missions against the occupying German army. Same
rules as everything in this repo: **pure C, zero libraries, zero asset
files** — every texture, sprite, sound, and letter is generated by code.

*Setting note: the player fights against the occupying forces (the
genre-classic Wolfenstein framing), which also makes the requested
tactics — ambushes, breaking defensive lines, surviving counterattacks —
the literal historical playbook of the resistance.*

---

## 1. Design pillars

1. **Tactics you can read.** Grid-based worlds keep sightlines, cover,
   and flanks legible. Every enemy behavior must be observable and
   learnable — no cheating AI.
2. **Everything hand-made.** The no-libraries constraint is the
   project's identity. New tech (threads, sound, particles) uses only
   OS calls.
3. **Short missions, high replay.** 5–10 minute missions with par
   times and a persistent best-times file. Restart in one keypress.
4. **60+ FPS floor.** Never ship a milestone below 60 FPS at 960×540
   on this machine (currently ~270 FPS; budget spent deliberately).

---

## 2. Gameplay systems (build order)

### Phase C — Combat core
- **Weapon viewmodel**: procedural pixel-art rifle at bottom-center;
  walk bob, recoil kick, 2-frame muzzle flash. Later: silenced pistol
  (stealth) and captured MP40 (loud, ammo-hungry).
- **Shooting**: hitscan reusing the DDA walk (`render_frame`'s ray loop
  refactored into `cast_ray()` used by both renderer and gameplay).
  Spread cone widens while moving; first-shot accuracy rewards ambush
  play.
- **Enemies**: soldier sprites via the existing billboard/zbuf pass.
  Health, hit reactions (1-frame white flash), 2-frame death, bodies
  persist.
- **Player**: HP, ammo, medkit and ammo pickups (reuse gold-pickup
  logic), damage direction indicator, death + quick restart.

### Phase A — The tactical brain (enemy AI)
- **Senses**: vision = one `cast_ray()` toward player + FOV cone check;
  hearing = gunshot event with radius (silenced weapon shrinks it).
- **State machine per soldier**: `PATROL → SUSPICIOUS (investigate) →
  ALERT (engage) → COVER → FLANK → FALLBACK`. States are visible in
  behavior: suspicious soldiers walk to the noise, alerted ones shout
  (HUD text + sound) and spread out.
- **Pathfinding**: BFS flood-fill flow field on the grid (24×24 → 48×48
  maps), recomputed on alert; soldiers follow the gradient. Cheap,
  perfect for grid worlds, ~50 lines.
- **Squads**: 3–5 soldiers share an alert state and a role split:
  one suppresses (fires from cover), one flanks left/right via flow
  field biased around the player, leader falls back if squad loses 50%.
- **Suppression**: near-miss shots raise a soldier's suppression meter →
  worse aim, stays in cover. Works on the player too (screen shake +
  blur edge vignette).

### Phase T — Tactics layer (the requested set pieces)
- **Defensive lines (theirs)**: maps define `defense nodes` (sandbag
  walls, MG nest cells, chokepoints) with priorities. Garrison mans
  line 1; when breached or flanked, they conduct a fighting withdrawal
  to line 2. MG nests create suppression corridors the player must
  flank — frontal assault should feel wrong.
- **Offensive pushes (theirs)**: after an objective is hit, timed
  counterattack waves arrive at map edges and advance cover-to-cover
  using bounding overwatch (half the squad moves while half aims).
- **Ambushes (yours)**: placeable satchel charge + tripwire (2 max),
  detonator key; convoy missions have patrol routes shown by scouting
  (binocular key highlights routes on minimap) so you pick the kill
  zone, open fire, and fade before reinforcements arrive.
- **Alarm system**: officers (distinct cap sprite) run for alarm posts
  when alerted; alarm = infinite reinforcement timer until switched
  off. Cutting the alarm wire pre-fight is the stealth reward.

### Phase M — Missions (3 archetypes, replayable)
1. **Convoy ambush** (offense): scout the route, set charges, spring
   the ambush, escape to the extraction cell before the response squad
   pins you.
2. **Radio post sabotage** (infiltration): sneak or fight through a
   defended farmhouse compound, demolish the radio, survive the
   counterattack push, escape.
3. **Hold the line** (defense): defend a bridge cell against N waves
   with pre-placed sandbag nodes you garrison — the defensive-line
   system, but yours.
- Mission select on the title screen (new game state), par times and
  best times saved to `maquis.sav` (hand-written save format, of
  course).

## 3. Graphics plan ("perfect" within raycaster rules)

The raycaster look — chunky texels, one-point perspective — is the
aesthetic. We polish *inside* it until it looks intentional, like a
lost 1994 classic.

- **Resolution & speed**: 1280×720 default; multithreaded column
  rendering via `CreateThread` (N worker slices over screen columns) —
  the renderer is embarrassingly parallel. Target: 200+ FPS at 720p,
  leaving headroom for particles.
- **Texture set v2**: 128×128 procedural textures — stone farmhouse,
  timber framing, sandbags, camo netting, bunker concrete, hedgerow
  foliage, cobblestone road, plus door and window variants. Same
  hash-noise toolkit, richer layering (base → blocks → grime → edge
  wear).
- **Directional animated sprites**: soldiers rendered from 4 view
  angles (front/back/left/right) × states (idle, 2-frame walk, aim,
  fire, hit, 2-frame death) — a procedural pixel-soldier generator
  builds all frames from one parameterized skeleton (pose → boxes →
  shading), so uniforms/poses are code, not art files.
- **Lighting events**: muzzle flashes and explosions inject a brief
  point light — walls/floor near the source brighten for 2 frames
  (add a light term into the fog function). Sells every firefight.
- **Particles**: screen-space sprites with velocity/gravity — impact
  dust, wood splinters, shell casings, smoke puffs, explosion cloud.
  Fixed pool (256), one draw pass, depth-tested against `zbuf`.
- **Sky & outdoors**: outdoor cells render a sky gradient + procedural
  clouds instead of ceiling, with a sun-direction shading bias on
  walls (west faces brighter at dusk) for outdoor mission maps.
- **Doors**: sliding doors (the classic recessed half-cell render),
  lockable, breachable with charges.
- **Feedback polish**: screen shake (small, decaying), damage flash,
  low-HP edge vignette, hit markers, floating "+" pickups text using
  the 5×7 font, film-grain dither pass toggle.
- **Sound (Phase S, `waveOut`, all synthesized)**: gunshot = shaped
  noise burst + lowpass tail; ricochet whine; footsteps on stone vs
  wood; alarm bell; distant artillery ambience loop. A tiny mixer
  (8 voices, 22 kHz) on a second thread.

## 4. Technical architecture

- **File split at Phase C start** (single file has served its purpose;
  keep the no-libraries rule, add a 20-line Makefile for w64devkit):
  - `main.c` — window, loop, input (current windowing code)
  - `render.c` — walls/floors/sprites/particles/HUD
  - `assets.c` — texture/sprite/sound generators, font
  - `game.c` — player, missions, pickups, save file
  - `ai.c` — senses, state machine, flow fields, squads
  - `shared.h` — structs, constants
- **Entities**: one fixed array `struct Ent { kind, x, y, angle, state,
  hp, anim, squad, ... }` (max 64). Sprites render from it; AI ticks
  it. No allocations at runtime — everything static, as now.
- **Maps**: keep the paint-by-primitives builder, add per-cell flags
  (door, cover, defense-node priority, outdoor, alarm wire) packed
  into a second grid. Mission = map builder function + entity spawn
  list + objective script (tiny switch-based state machine, no
  scripting language needed).
- **Determinism**: keep all randomness through `hash2()` with a
  per-mission seed → replayable runs, debuggable AI.
- **Testing**: extend `--selftest` into `--replay` (record input
  deltas per frame to a file, play them back headless) so AI/gameplay
  changes can be verified by rerunning a recorded session and
  checking end-state (kills, time, position) — CI for a game with no
  test framework.

## 5. Milestones

| # | Deliverable | Definition of done | Est. |
|---|---|---|---|
| M1 | Combat core | Rifle with recoil + flash; 4 dumb soldiers that face and shoot you; HP/damage both ways; death+restart | 1 session |
| M2 | Soldier AI | Senses, full state machine, flow-field pathing; a squad hunts you credibly through the current map | 1–2 sessions |
| M3 | Tactics layer | Defense nodes + fighting withdrawal; counterattack waves; satchel/tripwire ambush kit; alarm officers | 2 sessions |
| M4 | Mission 1 (Convoy ambush) | Scouting, kill zone, escape timer, win/lose, best time saved | 1 session |
| M5 | Graphics pass 1 | 720p + threads, texture set v2, directional/animated soldiers, muzzle lighting, particles | 2 sessions |
| M6 | Missions 2–3 + sound | Sabotage + Hold-the-line missions; synthesized audio; title screen | 2 sessions |

Each milestone ends the same way this repo always has: build clean at
`-Wall -Wextra`, screenshot verified, FPS measured, committed, pushed.

## 6. Risks & scope guards

- **AI creep** — cap: 64 entities, 5-state FSM, one flow field per
  squad per second. Fancy behavior comes from simple rules + roles,
  not more states.
- **Art volume** — the procedural soldier generator is the whole
  strategy; if a frame looks wrong we fix the generator, not 40
  sprites.
- **Perf** — measure with `--selftest` after every milestone; the
  60 FPS floor is a hard gate before adding the next system.
- **Scope** — 3 missions, 3 weapons, 1 enemy faction. Anything else
  goes to a post-1.0 list.
